A scheduled task is work Copus repeats on a schedule. It holds three things: instructions saying what each run should produce, a schedule saying when, and a folder the task keeps from one run to the next. Copus opens a fresh conversation for each run and gives it the instructions as its message.

Your **Tasks** list holds two other kinds of task that run without you. A [multi-step task](/autonomous/multi-step-tasks) is one big job Copus drives to the end. The tasks Copus starts on its own come from your mail and calendar, and their results wait on the Home page. See [Work Copus starts before you ask](/working/before-you-ask).

This page covers how to:

- [Set up a scheduled task](#set-up-a-scheduled-task) by asking for it in a conversation
- [See what each run is given](#what-a-run-is-given), and what Copus keeps out of it
- [Find a task in the list](#where-your-tasks-live), and read its status
- [Read the schedule](#the-schedule-in-plain-english) Copus writes for you
- [Find the task's folder](#the-tasks-folder) and what earlier runs left there
- [Run, pause, and watch a task](#run-pause-and-watch-a-task)
- [Rename or delete a task](#rename-or-delete-a-task)

Make a scheduled task when you want the same result delivered again and again: a brief every weekday morning, a summary of last week every Monday, a check on your numbers at the start of each month. For a result you want once, start an ordinary task.

## Set up a scheduled task

You set a task up by asking for it in an ordinary conversation. Copus builds the result once with you, live, and saves the task only after you're happy with what it produced.

<Steps>
  <Step title="Ask for the recurring result">
    Type what you want and how often, such as "Every weekday morning, give me a brief on what moved in my sector overnight."
  </Step>
  <Step title="Watch Copus build it once">
    Copus produces the real result now, this once, using the same integrations, skills, and web access an ordinary request would get. Use this first result to judge whether the task is worth repeating.
  </Step>
  <Step title="Say what to change">
    Tell Copus what to add, cut, or reshape, until the output is what you'd want to read.
  </Step>
  <Step title="Agree the time and zone">
    Confirm the time and timezone Copus proposes, or name a different zone. Your own zone is the default.
  </Step>
  <Step title="Check the task once it is saved">
    Copus writes the instructions and saves the task. Check what the task will do, when the first run happens, and where the result goes. The task runs on the AI provider and model of the conversation you set it up in, not on the provider marked **Default**. See [AI providers](/concepts/ai-providers).
  </Step>
  <Step title="Approve who the task may reach">
    If the task emails or invites anyone, Copus shows a card headed **Who “task name” may reach**, listing their addresses. Remove anyone who shouldn't be there, then select **Approve**. A run emails nobody who isn't on that list, you included, so check that your own address is there when the task emails you.
  </Step>
</Steps>

Every run works from the instructions alone, so Copus writes them as a complete assignment.

<Note>
  Copus starts the first run at the next time the schedule names. If today's time has already passed when you save the task, the first run happens at the following slot.
</Note>

<Tip>
  You can edit a live task's instructions on its page. In the **Instructions** box, select **Edit** and type the change. Copus saves the text shortly after you stop typing, and again when you leave the field. The next run reads the new text. A run that's already going keeps the text it started with. To have Copus make the change, select **Update task** and say what should be different. Copus changes the schedule and the task's files from the same conversation. The task changes only when Copus changes its instructions, schedule, or files there.
</Tip>

## What a run is given

Copus gives each run four things.

- The instructions, as the message that starts the run.
- The task's folder, which holds what the task keeps and what earlier runs delivered.
- What recent runs did. Copus gives each run the summaries of the task's most recent runs, each with the path to that run's full work log.
- The facts in your memory: your global facts, the facts Copus keeps for this task, and the facts Copus keeps for that run alone. See [Memory](/context/memory).

Copus keeps the conversation you set the task up in out of every run, because that conversation can hold questions that have nothing to do with the task. Copus also keeps out the task's own conversation, the one you open with **Update task** on the task page.

<Note>
  Copus runs every scheduled run on **Autopilot**, because nobody is watching it. Copus acts without stopping for an ordinary approval. Copus decides from the instructions and what recent runs did, and records what it decided in the run's summary. When you write the instructions, say what Copus should do when something is ambiguous. A run can email and invite only the people you approved for the task. A run can't give anyone access to your Drive files or comment on them. If the instructions call for anyone else, Copus sends nothing, and the run stops to name who it needed. Copus also withholds the Chrome you're signed in to from every run, and refuses a credential file outright, because nobody is there to approve either. [Approvals and permissions](/control/approvals-and-permissions) covers both modes.
</Note>

## Where your tasks live

Your tasks are all in one list. Select **View all** under **Tasks** in the sidebar. The list holds the tasks you start, the tasks Copus starts on its own, and your multi-step and scheduled tasks, newest activity first. The columns are **Task**, **From**, **Status**, and **Last active**.

**From** reads `You` for a task you asked for, including every scheduled and multi-step task, and `Copus` for a task Copus started on its own.

**Status** on a scheduled task reads `Active`, `Running`, `Paused`, `Failed`, or `Done`. A multi-step task reads `Working` while the job is live, and `Paused`, `Failed`, or `Done` otherwise. A task Copus started on its own shows its own state, such as `Ready`, `Needs you`, or `Sent` with the time Copus sent the reply. Copus adds a `Needs you` badge beside the status when a run stopped to ask you for something. On a scheduled task, Copus removes the badge once a later run delivers. On a multi-step task, Copus shows the badge only for a step in the newest round.

**Last active** shows the time of the task's latest activity. The task's own page shows when the next run is due.

Search the list with **Search tasks…**. Copus matches your search against each task's name and its summary or description. The search covers every task, including tasks further down than you have scrolled. Select **Scheduled** or **Multi-step** from the menu beside the search box to see one kind, or **All tasks** to see everything. Select **Pinned** to see only pinned tasks, and **All** to see every task again.

## The schedule, in plain English

Copus shows the schedule as a sentence in plain English. Copus writes the sentence from the schedule each time it shows it, so the sentence always matches the timing.

| The schedule you asked for | How Copus writes it |
|---|---|
| Weekday mornings | `Every weekday at 7:00 AM Pacific` |
| Every evening | `Every day at 6:30 PM Pacific` |
| Once a week | `Mondays at 9:00 AM Pacific` |
| Twice a day | `Every day at 7:00 AM and 5:00 PM Pacific` |
| Start of the month | `The 1st of each month at 7:00 AM Pacific` |
| Through the working day | `Every hour from 7:00 AM to 6:00 PM Pacific` |
| Frequently | `Every 5 minutes on weekdays` |

Where the sentence names a clock time, Copus adds the timezone the way people say it, so `America/Los_Angeles` reads as `Pacific`, `America/New_York` as `Eastern`, and `Asia/Tokyo` as `Japan`. Copus leaves out the standard-or-daylight half of the name, so the line stays the same all year. Copus keeps the schedule in that zone across daylight saving, so a 7:00 AM task stays at 7:00 AM.

Copus shows the sentence on the task's row in the list, and in the **Schedule** box on the task's page.

<Note>
  For an unusual schedule with no natural wording, Copus shows the schedule as it's stored and adds the zone, like `On the schedule "0 7 L * *" (Pacific)`.
</Note>

## The task's folder

Copus keeps a folder for each task that outlives any single run. Open the task and select **Artifacts** in the top bar to see it. The folder holds two kinds of file.

The first kind is what the task reuses. If each run needs the same data pull or the same chart, Copus writes a script once and stores it there, so later runs reuse the script. Copus makes judgment calls fresh in each run, such as which items matter, what the numbers mean, and what to say about them.

The second kind is what earlier runs delivered. Copus puts each run's result in the folder as well as sending it wherever the instructions say.

You can open and edit anything in that folder yourself, and Copus uses your changes on the next run. The folder sits under `CopusData/projects` in your home folder. Copus always keeps a scheduled task's folder there, even when you set it up from a conversation inside a project.

The task's page shows what every run is given in its **Instructions** box. Select **Memory** in the top bar to see the facts Copus keeps for this task alone. See [Memory](/context/memory). When the task has approved people, a **People** box lists who the task may email and invite. Select **Manage** to add or remove an address.

<Note>
  Copus keeps only a task's most recent runs. Past that limit, Copus deletes the oldest run's conversation and workspace, including that run's scratch files. Copus keeps everything a run delivered into the task's folder, so results outlive the runs that wrote them.
</Note>

## Run, pause, and watch a task

The task's page lists its runs under **Runs**, with the count beside it. Select a run to see what it reported, what it's waiting on, and the files it delivered. To read everything the run did, select **Open run** on its card.

Select **Run now** to start a run without waiting for the next slot. Select **Pause** to stop the schedule, and **Resume** to start it again. To change what the task does, select **Update task** to open the task's own conversation, and tell Copus what should be different.

A run card shows `Needs you` when the run stopped to ask you for something, `Failed` when the run couldn't finish, and `Trying again` with the wait remaining when Copus is about to retry the run, or `Retry held` while the task is paused. A run that is queued, working, or done carries a mark instead of a word. Copus leaves a run marked `Needs you` for you to answer and doesn't retry it.

<Note>
  Copus gives a run that stops part-way up to three attempts, with a wait between them, and the card counts them as `Attempt 2 of 3`. Copus cancels a run that shows no activity for a long stretch, so the task can move on, and then retries the run like any other failure. Copus waits out your provider's usage limit without spending an attempt.
</Note>

If several runs fail in a row, Copus stops the task and sets its status to `Failed`. Copus sends you a notification headed with the task's name and "stopped itself", and the task page reads "This task stopped itself after several runs failed in a row. Resume it once the cause is sorted." Fix the cause of the failures, then select **Resume**.

<Warning>
  Copus runs a scheduled task only while Copus is open and your Mac is on and awake. When you open Copus after it missed a slot, Copus runs the task once to catch up, then returns to the schedule. After a long gap with many missed slots, Copus still runs one catch-up run.
</Warning>

## Rename or delete a task

Select **Task actions** in the header, then **Rename** or **Delete**. **Delete** in that menu deletes the task at once, with no confirmation. **Delete** on the task's row in the **Tasks** list, or in the sidebar, asks you to confirm in the **Delete task?** dialog first. Either way, Copus deletes the task, every run it has had, and its whole folder. You can't keep the folder, so copy anything you want first.
