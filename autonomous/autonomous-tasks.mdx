A scheduled task is work Piper repeats on a schedule. It holds three things: instructions saying what each run should produce, a schedule saying when, and a folder the task keeps from one run to the next. Piper opens a fresh conversation for each run and gives it the instructions as its message.

Your **Tasks** list holds two other kinds of task that run without you. A [long-running task](/autonomous/long-running-tasks) is one big job Piper drives to the end. The tasks Piper starts on its own come from your mail and calendar, and their results wait on the Home page. See [Work Piper starts before you ask](/working/before-you-ask).

This page covers how to:

- [Set up a scheduled task](#set-up-a-scheduled-task) by asking for it in a conversation

- [Find a task in the list](#where-your-tasks-live), and read its status

- [Run, pause, and watch a task](#run-pause-and-watch-a-task)
- [Rename or delete a task](#rename-or-delete-a-task)

Make a scheduled task when you want the same result delivered again and again: a brief every weekday morning, a summary of last week every Monday, a check on your numbers at the start of each month. For a result you want once, start an ordinary task.

## Set up a scheduled task

You set a task up by asking for it in an ordinary conversation. Piper builds the result once with you, live, and saves the task only after you're happy with what it produced.

<Steps>
  <Step title="Ask for the recurring result">
    Type what you want and how often, such as "Every weekday morning, give me a brief on what moved in my sector overnight."
  </Step>
  <Step title="Watch Piper build it once">
    Piper produces the real result now, this once, using the same integrations, skills, and web access an ordinary request would get. Use this first result to judge whether the task is worth repeating.
  </Step>
  <Step title="Say what to change">
    Tell Piper what to add, cut, or reshape, until the output is what you'd want to read.
  </Step>
  <Step title="Agree the time and zone">
    Confirm the time and timezone Piper proposes, or name a different zone. Your own zone is the default.
  </Step>
  <Step title="Check the task once it is saved">
    Piper writes the instructions and saves the task. Check what the task will do, when the first run happens, and where the result goes. The task runs on the AI provider and model of the conversation you set it up in, not on the provider marked **Default**. See [AI providers](/concepts/ai-providers).
  </Step>
</Steps>

Every run works from the instructions alone, so Piper writes them as a complete assignment.

<Note>
  Piper starts the first run at the next time the schedule names. If today's time has already passed when you save the task, the first run happens at the following slot.
</Note>

<Tip>
  You can edit a live task's **Instructions** on its page. Piper saves the text shortly after you stop typing, and again when you leave the field. The next run reads the new text. A run that's already going keeps the text it started with. For anything else, including the schedule and the task's files, select **Ask Piper** and say what should be different. The task changes only when Piper changes its instructions, schedule, or files from that conversation.
</Tip>

## What a run is given

Piper gives each run four things.

- The instructions, as the message that starts the run.
- The task's folder, which holds what the task keeps and what earlier runs delivered.
- What recent runs did. Piper gives each run the summaries of the task's most recent runs, each with the path to that run's full work log.
- The facts in your memory: your global facts, the facts Piper keeps for this task, and the facts Piper keeps for that run alone. See [Memory](/context/memory).

Piper keeps the conversation you set the task up in out of every run, because that conversation can hold questions that have nothing to do with the task. Piper also keeps out the task's own conversation, the standing thread behind **Ask Piper** on the task page.

<Note>
  Piper runs every scheduled run on **Autopilot**, because nobody is watching it. Piper acts without stopping for an ordinary approval. Piper decides from the instructions and what recent runs did, and records what it decided in the run's summary. When you write the instructions, say what Piper should do when something is ambiguous. Piper also withholds the Chrome you're signed in to from every run, and refuses a credential file outright, because nobody is there to approve either. [Approvals and permissions](/control/approvals-and-permissions) covers both modes.
</Note>

## Where your tasks live

Your tasks are all in one list. Select **View all** under **Tasks** in the sidebar. The list holds the tasks you start, the tasks Piper starts on its own, and your long-running and scheduled tasks, newest activity first. The columns are **Task**, **From**, **Status**, and **Last active**.

**From** reads `You` for a task you asked for, including every scheduled and long-running task, and `Piper` for a task Piper started on its own.

**Status** on a scheduled task reads `Active`, `Running`, `Paused`, `Failed`, or `Done`. A long-running task reads `Working` while the job is live, and `Paused`, `Failed`, or `Done` otherwise. A task Piper started on its own shows its own state, such as `Ready`, `Needs you`, or `Sent` with the time Piper sent the reply. Piper adds a `Needs you` badge beside the status when a run stopped to ask you for something. On a scheduled task, Piper removes the badge once a later run delivers. On a long-running task, Piper shows the badge only for a step in the newest round.

**Last active** shows the time of the task's latest activity. The task's own page shows when the next run is due.

Search the list with **Search tasks…**. Piper matches your search against each task's name and its summary or description. The search covers every task, including tasks further down than you have scrolled. Select **Scheduled** or **Long-running** from the menu beside the search box to see one kind, or **All tasks** to see everything. Select **Pinned** to see only pinned tasks, and **All** to see every task again.

## The schedule, in plain English

Piper shows the schedule as a sentence in plain English. Piper writes the sentence from the schedule each time it shows it, so the sentence always matches the timing.

| The schedule you asked for | How Piper writes it |
|---|---|
| Weekday mornings | `Every weekday at 7:00 AM Pacific` |
| Every evening | `Every day at 6:30 PM Pacific` |
| Once a week | `Mondays at 9:00 AM Pacific` |
| Twice a day | `Every day at 7:00 AM and 5:00 PM Pacific` |
| Start of the month | `The 1st of each month at 7:00 AM Pacific` |
| Through the working day | `Every hour from 7:00 AM to 6:00 PM Pacific` |
| Frequently | `Every 5 minutes on weekdays` |

Where the sentence names a clock time, Piper adds the timezone the way people say it, so `America/Los_Angeles` reads as `Pacific`, `America/New_York` as `Eastern`, and `Asia/Tokyo` as `Japan`. Piper leaves out the standard-or-daylight half of the name, so the line stays the same all year. Piper keeps the schedule in that zone across daylight saving, so a 7:00 AM task stays at 7:00 AM.

Piper shows the sentence on the task's row in the list, in the header of the task's page, and under **Schedule** in the rail beside it.

<Note>
  For an unusual schedule with no natural wording, Piper shows the schedule as it's stored and adds the zone, like `On the schedule "0 7 L * *" (Pacific)`.
</Note>

## The task's folder

Piper keeps a folder for each task that outlives any single run. Open the task and select **Artifacts** in the rail to see it. The folder holds two kinds of file.

The first kind is what the task reuses. If each run needs the same data pull or the same chart, Piper writes a script once and stores it there, so later runs reuse the script. Piper makes judgment calls fresh in each run, such as which items matter, what the numbers mean, and what to say about them.

The second kind is what earlier runs delivered. Piper puts each run's result in the folder as well as sending it wherever the instructions say.

You can open and edit anything in that folder yourself, and Piper uses your changes on the next run. The folder sits under `PiperData/projects` in your home folder. Piper always keeps a scheduled task's folder there, even when you set it up from a conversation inside a project.

The rail holds two more panels. Open **Instructions** to read what every run is given, and **Memory** to see the facts Piper keeps for this task alone. See [Memory](/context/memory).

<Note>
  Piper keeps only a task's most recent runs. Past that limit, Piper deletes the oldest run's conversation and workspace, including that run's scratch files. Piper keeps everything a run delivered into the task's folder, so results outlive the runs that wrote them.
</Note>

## Run, pause, and watch a task

The task's page lists its runs under **Runs**, with the count beside it. Expand a run to read its summary and open the files it produced, or select **Open run** to see each step Piper took in that run.

Select **Run now** to start a run without waiting for the next slot. Select **Pause** to stop the schedule, and **Resume** to start it again. Select **Ask Piper** to open the task's standing conversation, where you change what the task does. Open the **Activity** tab to read the task's scheduled events as plain sentences, like `Started a run`, `Caught up after the app was closed`, and `Skipped a slot: the previous run was still going`.

A run card shows `Needs you` when the run stopped to ask you for something, `Failed` when the run couldn't finish, and `Trying again` with the wait remaining when Piper is about to retry the run, or `Retry held` while the task is paused. A run that is queued, working, or done carries a mark instead of a word. Piper leaves a run marked `Needs you` for you to answer and doesn't retry it.

<Note>
  Piper gives a run that stops part-way up to three attempts, with a wait between them, and the card counts them as `Attempt 2 of 3`. Piper cancels a run that shows no activity for a long stretch, so the task can move on, and then retries the run like any other failure. Piper waits out your provider's usage limit without spending an attempt.
</Note>

If several runs fail in a row, Piper stops the task and sets its status to `Failed`. Piper sends you a notification headed with the task's name and "stopped itself", and the task page reads "This task stopped itself after several runs failed in a row. Resume it once the cause is sorted." Fix the cause of the failures, then select **Resume**.

<Warning>
  Piper runs a scheduled task only while Piper is open and your Mac is on and awake. When you open Piper after it missed a slot, Piper runs the task once to catch up, then returns to the schedule. After a long gap with many missed slots, Piper still runs one catch-up run.
</Warning>

## Rename or delete a task

Select **Task actions** in the header, then **Rename** or **Delete**. **Delete** in that menu deletes the task at once, with no confirmation. **Delete** on the task's row in the **Tasks** list, or in the sidebar, asks you to confirm in the **Delete task?** dialog first. Either way, Piper deletes the task, every run it has had, and its whole folder. You can't keep the folder, so copy anything you want first.
