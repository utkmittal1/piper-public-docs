A project groups related tasks and gives them shared context. It holds a name, a description of the work, standing instructions every task follows, the facts and rules Piper remembers for that work, reference files, and a shared folder for deliverables.

## When to make a project

Make a project when one piece of work runs across several tasks, such as a launch, a client, or a report you keep coming back to. A one-off job needs only a single task. Piper reads the project's description, its instructions, and its memory at the start of every task in it.

Piper takes the project's name and its description from the two questions it asks when you create the project, and you can't change the name or the description afterwards. You can change the instructions, the memory, and the sources whenever you like, so write the description carefully.

## Create a project and start working

<Steps>
  <Step title="Open Projects">
    Select **Projects** in the sidebar, then **+ New Project**.
  </Step>
  <Step title="Say what the work is">
    Your answer to **What are you working on?** becomes the project's name. Your answer to **What are you trying to get done?** becomes its description, which Piper reads at the start of every task in the project, so write it as a full brief on the work. Piper needs both answers. You can't change the name or the description afterwards.
  </Step>
  <Step title="Choose where it lives">
    Under **Where should it live?**, pick **New folder** to let Piper manage the project folder, or **Existing folder** to point the project at a folder of your own. Conversations in the project can then read and edit the files in your folder. Piper keeps everything it creates in one subfolder inside your folder. Piper refuses your home folder, its own `PiperData` folder, and any folder inside `PiperData`. Then select **Create**.
  </Step>
  <Step title="Start a task in it">
    On the project page, type into the message box under **Start a task in this project** and select **Send**. Piper opens the new task inside the project.
  </Step>
</Steps>

<Note>
  You can also move an existing task in later. Open the task, select **Task actions**, then **Add to project**. For a task already in a project, the item reads **Move to project**, and you select **Remove from project** underneath it to take the task back out. Piper disables both items while the task is running.
</Note>

## The context every task shares

Open the rail on the right of a project page to reach four panels. Every task in the project can read what you put in them.

**Artifacts.** This panel shows the project's shared deliverables folder. Any task in the project can write to the folder, and every other task can read the files in it. **Other files**, further down the same panel, lists the rest of the project folder.

**Instructions.** You write standing guidance here that every task in the project follows, such as tone, format, or constraints. Piper saves the text as you type. A project's instructions take priority over the standing instructions you wrote under **Settings**.

**Memory.** This panel holds the facts that hold true inside this project and nowhere else, such as a decision made, a constraint agreed, or a choice that shapes the work. Piper adds facts as it learns them, and you can write a fact yourself with **Add a fact**. When the project has rules, the panel lists them under **Rules**, above the facts, with a count of how many of the project's 10 rules are in use. Piper sends every rule with every message in the project. As the project's memory fills up, Piper suggests facts to combine or drop. See [Memory](/context/memory) for the three levels of memory, rules, and cleanup suggestions.

**Sources.** You add files here as context for the whole project, such as a brief, a contract, or a spreadsheet of last year's numbers. Piper gives every task in the project the list of its sources, each with a short summary, and reads the whole file when the task needs it. Piper reads each file where you keep it, and marks the file **Missing** if you move it.

<Note>
  A project accepts sources in these formats: PDF, DOCX, XLSX, XLS, CSV, MD, TXT, JSON, and HTML. Add files with **Add sources** in the **Sources** panel. When Piper can't summarize a source, select **Retry summary** in that source's menu.
</Note>

<Tip>
  Knowledge sources are folders of documents Piper indexes for every task, in a project or not. You set them up in **Settings**. See [Knowledge Sources](/context/knowledge-sources).
</Tip>

## The project folder

The project header shows the folder the project lives in. Select that path to open the folder in Finder.

Piper keeps its own files in three folders. `artifacts/` holds the shared deliverables, `sessions/` holds one workspace folder per task, and `session-logs/` holds each task's work log. When a long-running task belongs to the project, Piper adds a `tasks/` folder, with a folder inside it for each long-running task. Piper keeps scheduled tasks outside projects, so their folders never sit here.

Where those folders sit depends on the choice you made when you created the project. For a project Piper manages, they sit at the top of the project folder, under `PiperData/projects` in your home folder, and the header shows that folder. For a project pointed at a folder of your own, the header shows your folder. Piper puts its folders in a subfolder it creates inside yours, with a name that starts with `piper-project-`. Conversations in that project can still read and edit the rest of your folder. A long-running task in the project can write only inside Piper's subfolder.

## The progress each task writes

Piper records each task's progress as the task goes. Inside a project, Piper shares that record with the other tasks.

Piper writes a short snapshot of where each conversation has got to, and gives every task in the project the other tasks' snapshots. Piper also keeps a dated work log for each task, as a file in the project's `session-logs/` folder, and reads a full log when it needs the detail behind a snapshot. Piper starts each new task in the project with what it recorded for the earlier tasks.

The project's **Tasks** list holds its long-running tasks alongside its conversations, most recently active first.

## Find, pin, or delete a project

Piper orders the **Projects** page by most recent activity. Each project card shows the project's description, how many tasks the project holds, and how long ago the project was last active. To find a project by name, type into **Search projects…**. On a project page, type into **Search tasks…** to find a task in that project.

Pin the projects you keep returning to, then select **Pinned** above the list to see only those projects. Piper leaves a pinned project in its place in the list. To pin a project, select **Pin project** on the project page, or the pin icon on the project card.

Select **Delete project** on the project page to remove the project and its conversations. Piper leaves the files you added as sources where they are. To remove the folder from disk as well, tick the option in the confirmation: **Also delete the project folder from disk** for a project Piper manages, or **Also remove Piper's subfolder from your folder** for a project that lives in a folder of your own.

Piper refuses to delete a project while a conversation in it is still working. Stop the conversation first.

<Warning>
  When you delete a project, Piper permanently removes everything in it, including its long-running tasks. Piper stops any step still running and deletes those tasks' folders from disk whether or not you tick the option.
</Warning>

<Note>
  When a project lives in a folder of your own, its conversations start in **Manual** approval mode, whatever you set as your default. Switch a conversation to **Autopilot** from the controls under the message box.
</Note>
