A task is a piece of work you asked Copus for. Copus runs three kinds of task and lists them together: a conversation, a multi-step task, and a scheduled task. A conversation is the ordinary kind, where you say what you need, Copus does it, and you go back and forth in the same thread. Copus works on the other two kinds without you there.

Copus gives every conversation a folder of its own to write files into, called a workspace. Copus gives each multi-step task and each scheduled task a folder that holds one workspace per step or per run.

## Start a task

Describe what you need on the Home page and select **Send**. To reach Home from anywhere, select **Home** in the sidebar. Everything that follows belongs to that task: the plan, the tools Copus uses, the files Copus writes, and the approvals Copus asks you for.

Copus names the task for you. Copus uses your first message as the title straight away, shortened if the message is long. A moment later, Copus replaces that stand-in with a short title it writes from the same message. When you rename a task yourself, Copus keeps your title, because Copus replaces only the stand-in title. If Copus can't write a title, Copus keeps the stand-in title.

## Choose which kind of task to start

Most tasks are conversations. You ask, Copus works, and you read the result and ask for the next thing. The rest of this page describes conversations.

Copus works on the other two kinds without you there. A **multi-step task** is for a job too big for one sitting, such as working through a folder of contracts. Copus writes a plan, splits the work into steps, and keeps working until the job is done. A **scheduled task** is for a result you want again and again, such as a brief every weekday morning. Copus runs the task at the time you agreed and leaves the result for you.

[Multi-step tasks](/autonomous/multi-step-tasks) and [Scheduled tasks](/autonomous/autonomous-tasks) cover those two kinds in full.

## Review tasks

When you ask Copus to have a piece of work reviewed, or agree when Copus offers a review, Copus starts a separate task titled **Review:** followed by the file's name. Copus lists the review task with your other tasks.

Copus runs the review task on the same provider and model as the task that asked for it, and starts it without that task's conversation. In the review task, Copus reads the files named in the request, checks them against the listed sources and standards, and sends its findings back to the task that asked. Copus leaves the work itself unchanged during a review. A review task runs without your standing instructions and your response style.

## The workspace a task writes to

Copus gives each conversation a workspace, a folder only that conversation writes to. The workspace has two parts:

- **`final-output/`** holds the finished deliverables, such as the document, the deck, the spreadsheet, or the analysis.
- **`intermediate-files/`** holds scratch and working material, such as notes, downloads, and half-built drafts.

A task can write files only inside its own folder, and macOS enforces that limit. For a conversation outside a project, that folder is its workspace. For a conversation in a project, that folder is the whole project folder, so conversations in a project can edit each other's files. A conversation can also write in [folders you add to it](#add-a-folder-copus-can-change).

A task can read files across your Mac. In every approval mode, Copus asks you each time a task tries to read a file that looks like a credential. [The sandbox](/control/sandbox) covers the boundary in full.

Copus puts the workspace of a conversation outside a project in `CopusData/sessions`, inside your home folder. For a conversation in a project, Copus puts the workspace in that project's `sessions/` folder. For a scheduled task, or a multi-step task outside a project, Copus creates a folder under `CopusData/projects`. For a multi-step task in a project, Copus creates that folder in the project's `tasks/` folder. Copus puts the workspaces of the task's steps and runs in that folder's own `sessions/`.

## Add a folder Copus can change

To have Copus work on files where they already live, such as a code repository or a folder of drafts, add that folder to the conversation. From your next message, Copus can create, edit, and delete files in it. Copus still keeps its scratch work and finished deliverables in the workspace unless you ask for them in the added folder.

To add a folder:

1. Select the plus button under the message box, then **Add folder**. The **Task actions** menu in the top bar has the same **Add folder** item.
2. Choose the folder.
3. Select **Allow** when Copus asks you to confirm.

Select the folder icon in the message box to see the folders you added. Select a folder's name to open it in Finder. The list has two actions:

- **Remove**: Copus takes the folder off the list, and from your next message it can't write there. Copus leaves the changes it already made in place.
- **Add folder**: Copus adds another folder after you confirm.

You can't add or remove a folder while Copus is replying. To give every conversation in a project the same folder, add it to the project instead. See [The project folder](/concepts/projects#the-project-folder).

When you switch a conversation that has folders to a multi-step task, Copus first asks you to confirm that the task can take them. Copus switches the conversation only after you select **Switch to multi-step** in that question. The task works on its own and doesn't ask before it runs a command, so it can create, edit, and delete files in those folders without asking you. To take a folder away from the task, select the folder name on the task's page, then **Remove**.

### Limitations

- **A conversation holds up to 10 added folders.** Remove a folder to add another.
- **Copus adds only folders inside your home folder or on an external drive.** In your home folder, it refuses the home folder itself, your `Library` folder, `CopusData`, and hidden folders, whose names start with a dot. It refuses anything inside those folders too.
- **Some files stay blocked inside an added folder.** The files no task can write anywhere stay blocked in your added folders too. [The sandbox](/control/sandbox#files-no-task-can-write) lists them.
- **Scheduled tasks never get added folders.**
- **You can't add a folder to a multi-step task after it starts.** The task keeps only the folders its conversation had when it switched to multi-step.
- **Copus never moves, renames, or deletes an added folder.** Deleting the conversation leaves the folder where it is.

## Open the files a task made

Select **Artifacts** in the top bar of a task. **Artifacts** lists the finished deliverables, along with anything the task wrote to the shared folder of the project or task it belongs to. **Other files**, further down the same panel, lists everything else in the task's folder, in the folders Copus wrote it to.

Select **Open folder in Finder**, on the **Other files** heading, to open the whole folder on your Mac. The same item sits in the **Task actions** menu in the top bar.

<Tip>
  Hover a file row to see the file's full path on your Mac. To find the file itself in Finder, use **Show in Folder** in the file viewer's **File actions** menu.
</Tip>

## What belongs to one task alone

Three settings apply to one task alone.

**Instructions.** Select **Instructions** in the task's top bar and write standing guidance for this task, such as "answer in French" or "keep every figure to two decimal places." Copus saves the text as you type, and reads the instructions again with every message. Instructions you want in every task belong on the **Instructions** page in the sidebar. See [Instructions and profile](/context/instructions-and-profile).

**Approval mode.** Each conversation runs in **Manual** or **Autopilot**, set from the controls under the message box. In **Manual**, Copus asks you by default before it sends, posts, or changes anything in a connected app, and before it runs a command that changes something on your Mac. In **Autopilot**, Copus does these without asking. A new task starts in **Manual**. To start every new task in **Autopilot** instead, open **Settings**, select **Built-in tools**, and change **New tasks start in**. A task in a project you pointed at a folder of your own starts in **Manual** either way. See [Approvals and permissions](/control/approvals-and-permissions).

**Planning mode.** Turn on the **Planning mode** switch in the task's top bar to see Copus's plan before Copus starts. Copus writes its task list and waits. Select **Go ahead** to start, or tell Copus what to change, and Copus revises the list and waits again. With the switch off, Copus carries out its plan straight away. A new task starts with **Planning mode** off.

<Note>
  A multi-step task's steps and a scheduled task's runs start on **Autopilot**, because nobody is there to answer. When a step or a run tries to read a file that looks like a credential, Copus refuses for the same reason.
</Note>

## Rename, pin, move, or delete a task

The sidebar lists your recent tasks under **Tasks**, as many as fit its height. Select **View all** beneath them for the full list.

The full list has three controls. Type into **Search tasks…** to narrow the list. Use the menu reading **All tasks**, **Scheduled**, or **Multi-step** to show one kind of task. Select **Pinned**, beside that menu, to see only the tasks you pinned, and **All** to see every task again.

<Steps>
  <Step title="Rename a task">
    Open the task, select **Task actions** in the top bar, then **Rename**. Type the new name and select **Save**.
  </Step>
  <Step title="Pin a task">
    Pin the tasks you keep returning to, such as a task that holds reference material, so they stay easy to find once the list runs long.

    Select **Pin task** from the same menu, or **Pin** on the task's row in the list.
  </Step>
  <Step title="Move a task into a project">
    Select **Add to project** from the menu, then pick a project or select **Start a new project**. For a task already in a project, select **Move to project** to change it, or **Remove from project** to take it back out.
  </Step>
  <Step title="Delete a task">
    Select **Delete**, then confirm in the **Delete task?** dialog. Copus leaves the workspace folder on disk unless you tick **Also delete the folder from disk** first.
  </Step>
</Steps>

To delete several tasks at once, tick their rows in the full list and select **Delete** in the bar above them. The checkbox in that bar ticks every row on screen. When more tasks match than the list has loaded, select **Select all** with the number of matching tasks beside it to include every one of them.

<Warning>
  When you delete a multi-step or scheduled task, Copus removes the task, its steps and runs, and its folder, and you can't keep the folder. When you tick a mix of conversations and multi-step or scheduled tasks, the folder option in the delete dialog applies only to the conversations. Copus deletes the folders of the multi-step and scheduled tasks whatever you tick.
</Warning>

<Note>
  Copus refuses to delete a conversation that is still working, or to move it into a project. Stop the conversation first, or wait for it to finish. You can't rename, pin, move, or delete a multi-step or scheduled task's own conversation.
</Note>

## Tasks inside a project

Copus keeps the workspace of a task in a project inside the project's folder. The task can read and write across the whole project folder, so tasks in the same project can build on each other's files. Copus still puts a task's own finished work in its `final-output/`. Copus puts work meant for the whole project in the project's **Artifacts** folder, which every task in the project can reach. [Projects](/concepts/projects) covers the shared context in full.
