A knowledge source is a folder of documents you add for Piper to search. Piper reads the supported files in that folder, splits their text into passages (called chunks), and builds a search index on your Mac. Your documents stay where they are, and Piper never writes to them.

Add a folder when its documents hold background Piper may need across different tasks: past decks, research, notes, contracts. A [project source](/concepts/projects) is the better place for a file only sessions in one project need.

## Setting up knowledge search

Two things have to be true before Piper can search your documents. Piper needs the **Search knowledge** tool switched on, and at least one folder has to be indexed. The tool starts on, so adding your first folder is usually the whole setup.

<Steps>
  <Step title="Check the tool is switched on">
    In **Settings**, select **Tools**, and look for the **Search knowledge** row. It is on to begin with. The row is marked read and **Always runs**, so Piper searches without stopping to ask you. Clear the checkbox to stop Piper searching your folders at all.
  </Step>
  <Step title="Add a folder">
    In **Settings**, select **Knowledge Sources**, then **Add a folder**, and pick the folder you want. Piper names the source after the folder.
  </Step>
  <Step title="Wait for indexing to finish">
    Indexing starts on its own. The card's status reads **Up to date** once the folder is searchable. Until one source holds an indexed passage, Piper is not told it has any knowledge, whatever the tool is set to.
  </Step>
</Steps>

Piper walks the whole tree, subfolders included. It refuses a folder that is already a source, so the same folder cannot be indexed twice.

<Note>
  Every agent has its own copy of this switch. **Settings**, then **Tools**, sets it for the built-in agent, named **Piper**, and Piper has no control for handing a task to any other agent. A [custom agent](/autonomous/custom-agents) keeps its own switch on its own **Tools** tab, and no session runs on it.
</Note>

## Which files get indexed

Piper indexes eight file types and skips everything else:

| Type | Extensions |
|---|---|
| Documents | `.docx`, `.pdf` |
| Spreadsheets | `.xlsx`, `.csv` |
| Slides | `.pptx` |
| Text | `.md`, `.txt`, `.xml` |

Everything else stays untouched, including `.json` and `.html`, which are usually machine output rather than something you wrote. Piper also skips hidden files and folders, Office lock files, and symbolic links, so the index stays clean. One file it cannot read never stops the pass: Piper skips that file and indexes the rest of the folder.

<Note>
  Piper sets no limit on how many folders you add, how many files a folder holds, or how large a file is. Large folders and large files take longer to index.
</Note>

## Reading a source card

Each folder has a card. It shows the folder's name, where it sits on disk, a status, and two counts.

| Status | What it means |
|---|---|
| **Queued** | Waiting its turn to be indexed |
| **Indexing…** | Being read now, with a count of files done out of the total |
| **Up to date** | Indexed and searchable |
| **Needs attention** | Piper could not find the folder where you added it, or the on-device search model is not ready. That model is what turns text into the numbers Piper compares, and Piper downloads it once and keeps it on your Mac. The reason sits behind the info icon |
| **Couldn't index** | The folder could not be read, with the reason behind the info icon |

The two counts are files and passages. A passage is a chunk of about 1,000 characters, and consecutive chunks overlap by about 200 characters so a sentence spanning a boundary survives. One long PDF becomes many passages, which is why the passage count runs far ahead of the file count. A card that is up to date also shows when the folder's contents last changed.

## How Piper keeps a folder's index current

Piper watches each folder for changes. It starts an update once the folder has been quiet for five seconds, checks every folder every 30 minutes, and runs a check when Piper starts up. A pass over a folder that has not changed does nothing and leaves the card's date alone, so "Updated 2 hours ago" keeps meaning the last time the contents actually changed.

You can also force a pass. Select **Re-index** on a card and Piper checks the folder straight away. It re-reads only the files that changed, so a re-index of a settled folder is quick.

## Removing a folder

Select **Remove source** on the card, then **Remove** to confirm. That drops the folder from the search index and leaves your documents exactly where they were.

## How Piper searches

Piper compares the meaning of your question with the meaning of each indexed passage, which is called semantic search. It returns the closest passages, up to ten by default, each with the file it came from and a score between 0 and 1. Because it matches on meaning, a search for "pricing objections" can surface a passage about customers pushing back on cost, even where neither of those words appears.

Piper looks at your knowledge early in a task, while it is still working out what you are asking for, so a source can shape the answer even when you never mention it. Where nothing relevant comes back, Piper says so rather than implying it found something.

<Warning>
  Piper builds and searches the index on your Mac. When Piper uses a passage in a task, that passage goes to your AI provider along with the conversation. See [Your data stays local](/control/your-data-stays-local) for where the boundary sits.
</Warning>

Three neighbouring features are easy to confuse with a knowledge source. [Memory](/context/memory) holds short facts about you, not documents. [Integrations](/connections/integrations) connect Piper to live apps such as Gmail and Notion. A project source is a single file attached to one project, covered on the [Projects](/concepts/projects) page.
