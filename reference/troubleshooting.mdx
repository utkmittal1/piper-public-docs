This page lists the states Piper can end up in and the fix for each. Find the wording on your screen in a heading below, then follow the steps under it. You make most fixes inside Piper. You make three fixes outside Piper, and each of those entries says where to go: installing `uvx`, installing the Chrome extension, and allowing notifications in macOS.

Jump to the group your problem sits in:

- [When Piper will not start work](#when-piper-will-not-start-work), including a signed-out provider
- [When a connection breaks](#when-a-connection-breaks), for an expired integration, an integration that failed to start, or a website sign-in
- [When a tool will not run](#when-a-tool-will-not-run), because it expired or is switched off
- [When your documents are not searchable](#when-your-documents-are-not-searchable), for a knowledge source that won't index
- [When background work stalls](#when-background-work-stalls), for scheduled tasks, the Home page, and banners
- [Questions people ask](#questions-people-ask), on logs, memory, and files that won't open

## When Piper will not start work

<AccordionGroup>
  <Accordion title="The Home page shows Sign in to an AI provider">
    You haven't signed in to an AI provider or saved a model API key, so Piper has nothing to run a task on. Until you do, the Home page shows the **Sign in to an AI provider** step in place of the message box. Select **Sign in**, then sign in to Claude Code or Codex, or paste an API key for Anthropic, OpenAI, or DeepSeek. You can also do this in **Settings** > **AI Providers**. [AI providers](/concepts/ai-providers) covers what each option needs.
  </Accordion>

  <Accordion title="A red banner says your default provider is signed out">
    The banner reads one of two ways. If a sign-in that was working has stopped, the banner says new tasks, and the work Piper starts on its own, will fail until you sign in again. If you haven't signed that provider in yet, the banner tells you to sign in once, or set up another provider, before starting a task. Select **Sign in** on the banner. You can also sign in from **Settings** > **AI Providers**, where you choose which provider to use and where your API keys live.
  </Accordion>

  <Accordion title="Could not start, or Could not send">
    **Could not start** appears under the message box on the Home page when a new task fails to open. **Could not send** appears at the bottom of a task when a message fails. Piper shows the reason under each, and the reason usually names the cause. If the reason points at your sign-in, select **Sign in** on the red banner, then send again.
  </Accordion>

  <Accordion title="A task says your provider is signed out or has no API key">
    Piper shows a warning banner below the message box, in the spot where **Could not send** appears. Its title says what went missing: the provider is signed out, the provider has no API key any more, or the provider no longer offers the model this task was using. Under the title it reads `Pick an AI provider for this task to carry on.` Piper keeps your task as it was. Use the provider and model picker under the message box to choose a pair that works, then send again.
  </Accordion>
</AccordionGroup>

## When a connection breaks

<AccordionGroup>
  <Accordion title="Gmail needs to reconnect.">
    A banner with this title, naming one app or counting several, means a sign-in expired. Under the name it reads `Their sign-in expired; their tools are paused until you reconnect.` Select **Open Integrations**. Open that app's card, marked with a **Reconnect** badge, to see **Needs reconnect** and the reason. Every other integration keeps working meanwhile. If you dismiss the banner, Piper keeps it hidden while that app stays broken, until you quit and reopen Piper. Piper also shows the banner again if that app reconnects and then breaks a second time.
  </Accordion>

  <Accordion title="Notion failed to start.">
    A red banner with this title, naming one app or counting several, means Piper couldn't start the server that gives Piper that app's tools. Under the name it reads `Their servers did not start; their tools are left out until they do.` Piper leaves that app's tools out of every new task until the server starts. Every other integration keeps working.

    Select **Open Integrations**. The app's card carries a red **Failed to start** badge. Open the card to read the reason above the app's tools. The reason reads one of these ways:

    | The reason reads | What it means |
    |---|---|
    | `A session could not start the server. Piper is checking why.` | A task couldn't start the server, and Piper is checking it. Wait a moment, and Piper replaces the reason with what it found. |
    | `The server did not answer in time when a session started it.` | The server was too slow to start for a task. |
    | `The server did not answer within 15 seconds.` | Piper started the server, and the server didn't answer in time. |
    | `Piper could not run` followed by a command name and `command not found.` | A program the server needs is missing from your Mac. |
    | `The server stopped before it was ready.`, `Piper could not start the server:`, or `The server refused to list its tools:` | The server started and then failed. The rest of the line gives the server's own error. |
    | `Piper could not reach the server:` or `The server responded with HTTP` followed by a code | Piper couldn't reach an app that runs online, or the app answered with an error. |
    | `The server rejected the stored credential. Disconnect it and add it again with the right key.` | A server you added yourself refused its key. Disconnect the server and add it again with the right key. |

    Select **Retry** beside the reason to try again now. A server you added yourself whose key was refused has no **Retry**. Piper also tries again on its own, and waits longer between tries while the server keeps failing. Once the server starts, Piper clears the **Failed to start** badge, and Piper gives new tasks the app's tools again.
  </Accordion>

  <Accordion title="A step in a task reads Notion didn't start">
    Piper started the task without that app's tools. The line under the step reads `Notion's server did not start, so its tools are not in this session. Integrations shows why.` Open **Settings** > **Integrations** and open the app's card for the reason and **Retry**. For a server that belongs to Piper itself, the line ends after `not in this session.`
  </Accordion>

  <Accordion title="A website needs you to sign in">
    Piper shows a card headed **Sign in needed** in the conversation. Select **Open sign-in window**, sign in as you normally would, then select **I've signed in**. You can also close the window yourself.

    Piper closes the window after a set time, whether or not you're still using it. Typing in the window doesn't extend the time, so a sign-in that needs a code from your phone can run out midway. The card then reads **Window closed** and offers **Open sign-in window** again, which starts the time again. If the save fails, the card reads **Sign-in not saved** with the reason, and you select **Try again** to restart the sign-in.
  </Accordion>

  <Accordion title="You want to remove a saved website sign-in">
    Piper has no screen for reviewing or deleting a saved sign-in. Piper keeps a saved sign-in for that site for every later task. [Web and sign-ins](/connections/web-and-sign-ins) covers saved sign-ins.
  </Accordion>

  <Accordion title="Piper can't use your own Chrome">
    Piper works in your Chrome through an extension. Open **Settings** > **Built-in tools**, and find the setting **Use my Chrome for sites I’m signed in to**. If the extension is missing, the setting offers **Set up**. Select it, and Piper explains that the Playwright team at Microsoft publishes the extension and offers **Install extension**. Install the extension and come back, and Piper turns the setting on when the extension is installed. If the extension is installed but switched off, a warning under the setting says so, and you turn the extension back on in Chrome.
  </Accordion>

  <Accordion title="Connecting AWS Documentation fails">
    AWS Documentation runs a helper program called `uvx` on your Mac, and Piper checks for `uvx` before connecting. If `uvx` is missing, Piper shows a message naming `uvx` and saves nothing. You install `uvx` outside Piper. Every other app in the catalog needs only a sign-in or a key.
  </Accordion>
</AccordionGroup>

## When a tool will not run

<AccordionGroup>
  <Accordion title="An action was Auto-denied">
    When nobody answers an approval card in time, Piper denies the action. Piper removes the card's buttons, marks the card **Auto-denied**, and tells you to ask again if you still want the action. Piper skipped the action. Ask for the same thing again and answer the new card, then select the × on the expired card to clear it.

    In work that runs with nobody watching, Piper never waits for an answer. In that work, Piper refuses your own Chrome and credential files as soon as they come up. In a task on **Autopilot** with you present, Piper answers most approval questions itself. Piper still asks you about credential files and your own Chrome, and waits for your answer. [Approvals and permissions](/control/approvals-and-permissions) explains the two modes.
  </Accordion>

  <Accordion title="Piper says a tool is turned off">
    Piper reports that the tool is turned off and skips the work. For one of Piper's own capabilities, open **Settings** > **Built-in tools**, find the capability, and switch it on. For an app's tool, open that app under **Settings** > **Integrations**, and switch the tool on in its **Read** or **Write** group. Piper leaves some of an app's tools off at first. [Built-in tools](/working/tools) and [Integrations](/connections/integrations) cover both screens.
  </Accordion>
</AccordionGroup>

## When your documents are not searchable

<AccordionGroup>
  <Accordion title="A source shows Couldn’t index or Needs attention">
    Both badges sit in **Settings** > **Knowledge**. Hover the info icon beside either badge to read the reason. Red **Couldn’t index** means indexing failed for the whole folder. Fix what the reason names, then select the refresh icon on that source to index it again.

    Amber **Needs attention** has three causes, and each takes a different fix.

    | The reason reads | What to do |
    |---|---|
    | `Preparing the on-device search model…` | Wait. Piper is downloading the search model, and indexes the folder once the download finishes. Indexing again now changes nothing. |
    | `The on-device search model is not available yet`, with the error in brackets | The download failed. Select the refresh icon on that source and Piper tries the download again before it indexes. |
    | That the folder could not be found at a path | The folder moved, or its drive is unplugged. Put the folder back at the path named, or plug the drive in, then select the refresh icon on that source. |
  </Accordion>

  <Accordion title="A source sits on Indexing… or Queued">
    Both badges are normal. **Queued** means the folder is waiting its turn. **Indexing…** means Piper is reading the folder, and a progress bar under the source counts files done against files total. The badge turns to **Up to date** when Piper finishes. Piper indexes on your Mac and keeps your files there, so a large folder takes time.
  </Accordion>
</AccordionGroup>

## When background work stalls

<AccordionGroup>
  <Accordion title="A scheduled task shows Failed, or one of its runs needs you">
    **Failed** in red on the task means Piper stopped the task after several runs failed in a row. Piper also marks the run that broke with its own **Failed** badge. If that run opened a conversation, select **Open run** on it to see what went wrong. Sort the cause, then select **Resume**.

    These badges belong to a single run. **Needs you** in amber means a run is waiting on you, so expand the run to see what for. **Trying again**, followed by when, means Piper tries the run again on its own at that time, and you don't need to act. When the task is paused, failed, or finished, the badge reads **Retry held** instead.
  </Accordion>

  <Accordion title="The Home page reads Can't check right now">
    Piper's last checks of your mail failed. Hover the info icon beside the line to read the reason. If the reason says an app's login lapsed, open **Settings** > **Integrations** and reconnect that app. Piper starts checking again once you reconnect the app. [Work Piper starts before you ask](/working/before-you-ask#when-piper-checks) covers when Piper checks.
  </Accordion>

  <Accordion title="macOS banners never appear">
    Turn on **macOS banners** in **Settings** > **Notifications**, and Piper sends a test banner. Piper shows **Not showing?** under the setting whenever the setting is on, even when nothing failed. Select **Open settings** beside it, then allow notifications for Piper on that macOS screen and set its style to Banners or Alerts. You make that change in macOS. If a toast titled **Test banner didn't send** appears, Piper failed to send the banner, and the reason sits underneath it.
  </Accordion>
</AccordionGroup>

## Questions people ask

<AccordionGroup>
  <Accordion title="Where do I see what Piper has been doing?">
    Open **Settings** > **Logs**. Piper streams its most recent events there, newest at the bottom, with one filter for the area (`session`, `trust`, `connection`, `background`, `notify`) and a second filter for the level (`info`, `warn`, `error`). The button on the right reads **Live** while the stream is running and **Paused** once you stop it. Select an event to expand its detail. **No events yet** means nothing has happened, or your filters are too tight.
  </Accordion>

  <Accordion title="Can I review a fact Piper saved just for one task?">
    Yes, but only on the reply where Piper saved it. Session memory has no page. Piper adds a note to the reply listing each fact it saved, and you change a session fact with **Undo** or **Edit** on that note, or by asking Piper. Your global facts sit in **About you** > **Memory**, and a project's facts sit on the project's own page. [Memory](/context/memory) covers each level.
  </Accordion>

  <Accordion title="A file won't open in Piper">
    `No preview available for this file type.` means Piper has no viewer for the file, and the file itself is fine. **Could not open this file** is a real failure, and the reason sits underneath. Most often the file is too large to view in Piper, or it was moved or deleted. Open the viewer's **File actions** menu, the button beside the file's name, and choose **Open in default app**. You can also select the folder icon on the file in the right-hand rail to show the file in Finder.
  </Accordion>
</AccordionGroup>

<Note>
  Piper works only from the sources and tools you connect. If an answer is missing information, check that Piper had what it needed connected before treating it as a bug.
</Note>

<Warning>
  Logs mostly record what Piper did, but they also hold some of your content. Piper writes the start of the message that begins each turn into the log, and the full text of a memory fact it removes or rewords. Read a log before you share it.
</Warning>
