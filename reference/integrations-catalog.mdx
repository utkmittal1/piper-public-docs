The integrations catalog is the set of connections Piper ships ready to make, with an entry for each app Piper already knows how to reach and sign in to. Each integration gives Piper tools that read, tools that write, or both.

An integration gives Piper the app's own tools, so Piper can search your mail or update a record directly. Without an integration, Piper can still open that app's website in [its own browser](/connections/web-and-sign-ins) and use the site the way you would. [Integrations](/connections/integrations) covers how to set an integration up and how to fix an integration whose sign-in expired or whose server failed to start.

## How to read the tables

Open **Settings**, then **Integrations**, to find any entry below. Each entry lists two things.

**What Piper can do** is the same line the integration's card shows on the **Integrations** page.

**What it asks you for** is what you have to supply. Each integration takes one of these routes.

| Route | What you supply |
|---|---|
| Piper's sign-in, or your own OAuth app | With Piper's built-in sign-in, nothing: you approve the sign-in page. The built-in sign-in works only for approved users. Everyone else selects **Set up your own app instead** and pastes the **Client id** and **Client secret** of an OAuth app they create in the provider's own console. |
| Browser sign-in | Nothing. Piper registers itself with the service when you connect, so you only approve the sign-in page. |
| API key | A key or token you generate in that service. |
| A command on your Mac | The `uvx` command, already installed on your Mac. You paste nothing. |

Open a connected integration's panel to see its tools, under a **Read** group and a **Write** group, with a checkbox and an **Auto** or **Ask** control on every tool.

## Which integrations make you paste something

Most integrations take no credential from you. For a browser sign-in, you only approve the page. AWS Documentation needs only `uvx` on your Mac. Atlassian is a browser sign-in with one extra step, described at the end of this section.

These integrations take a credential you create yourself:

- Excalidraw, Figma, and Firecrawl take an API key you generate in that service.
- GitHub takes a fine-grained personal access token, a GitHub token you scope to chosen repositories and permissions.
- Gmail, Google Drive, Google Calendar, and Slack take the **Client id** and **Client secret** of your own OAuth app, but only when your account isn't approved for Piper's built-in sign-in. You create the app in Google Cloud Console or at api.slack.com, after selecting **Set up your own app instead** in the integration's panel.

Piper puts each credential in your Mac's keychain and never shows it back on screen. When an integration's key stops working, Piper shows the boxes empty, and you paste the credential in again.

Atlassian needs one extra step from you besides the sign-in. Before the browser sign-in can succeed, an administrator of your Atlassian organization has to add Piper's redirect address, the address the sign-in comes back to, as a domain under the Rovo MCP server. The integration's panel lists the steps.

## What a tool does when it runs

A read tool looks something up. A write tool changes something in the connected app. Piper sets every write tool to **Ask**, and a few read tools in Canva and Firecrawl too.

In Manual, Piper asks you by default before it sends, posts, or changes anything in a connected app. In Autopilot, Piper does these without asking. In tasks Piper starts on its own, Piper runs every tool you switched on without asking, including tools set to **Ask**. In those tasks, Piper withholds the Gmail and Google Calendar write tools. [Approvals and permissions](/control/approvals-and-permissions) covers both modes.

Piper leaves some tools switched off when it adds an integration's tools, so a new connection starts with the common actions. Switch a tool on, or change whether it asks, on that integration's own panel. [Integrations](/connections/integrations) explains that panel.

## An app that is not in the catalog

Select **+ Add Custom** on the **Integrations** page. You can point Piper at any service that publishes an MCP server, the standard a service uses to offer its tools to an assistant like Piper, or at a program that runs on your Mac. [Integrations](/connections/integrations) covers that path.
