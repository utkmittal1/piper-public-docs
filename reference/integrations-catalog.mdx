The integrations catalog is the set of connections Piper ships ready to make, one for each app it already knows how to reach. It holds 26 integrations across 11 categories, and each one brings a fixed set of tools: 496 in all, 284 that read and 212 that write. Piper reaches an app only through an integration you connected. [Integrations](/connections/integrations) covers how to connect one and what happens when its credentials expire.

## How to read the tables

Open **Settings**, then **Integrations**, to find any entry below. Each one lists three things.

**What Piper can do** is the same line the integration's card shows on the Integrations page.

**Tools** is how many actions that integration gives Piper, split into reads and writes. Open a connected integration's panel and Piper shows the same split, under **Read** and **Write**. Select the tool count beside either one to list the tools themselves. Not all of them arrive switched on. 98 of the 496 ship off, so the count is what the integration offers, not what a new connection starts with.

**What it asks you for** is what you have to supply. There are four routes, and eight of the 26 make you paste a credential yourself.

| Route | What you supply | How many |
|---|---|---|
| Browser sign-in | Nothing. Piper registers itself with the service, so approving the sign-in page is the whole job. | 17 |
| Your own OAuth app | The **Client id** and **Client secret** of an OAuth app you create in the provider's own console, which is the registration it signs Piper in through. | 4 |
| API key | A key or token you generate in that service. | 4 |
| A command on your Mac | Nothing, apart from having `uvx` installed. | 1 |

| **AWS Documentation** | Search and read official AWS documentation pages. | 3 read | Nothing, once `uvx` is installed |

<Note>
  AWS Documentation is the one integration that asks for no account and no key. It runs on your own Mac, and it starts through `uvx`, a command that runs a Python program without installing it first. Piper checks for that command when you select **Connect**, and if it is missing the connection fails with a message naming it. Piper has no screen that installs it for you, so this is the one entry in the catalog you may not be able to finish inside Piper.
</Note>

## Which integrations make you paste something

Eighteen ask nothing of you beyond approving a sign-in page or, for AWS Documentation, having `uvx` installed. The other eight take a credential you create yourself:

- Gmail, Google Drive, Google Calendar, and Slack need an OAuth app you register in Google Cloud Console or at api.slack.com, and you paste its **Client id** and **Client secret** into Piper.
- Excalidraw, Figma, and Firecrawl take an API key you generate in that service.
- GitHub takes a fine-grained personal access token, a GitHub token you scope to chosen repositories and permissions.

An expired connection sends you back to the same box, since Piper keeps no copy it can paste in for you.

One integration asks something of you without asking for a credential. Atlassian needs an admin of your Atlassian organization to add Piper's redirect URI, the address the sign-in comes back to, as a domain for the Rovo MCP server before the browser sign-in will go through.

## What a tool does when it runs

A read tool looks something up and runs on its own. A write tool changes something in the connected app, and every one of them is set to ask you first. Six read tools are set to ask as well: four in Canva and two in Firecrawl. A session running on **Autopilot** answers those questions itself, which is what [Approvals and permissions](/control/approvals-and-permissions) covers.

Piper leaves 98 of the 496 tools switched off when it adds an integration's tools, so a new connection starts with the common actions and not every one on offer. Turn any of them on, or change whether one asks, in **Settings** > **Tools**. [Tools](/working/tools) explains that screen.

These counts only reach Piper once the integration's tools are added to it, which the connect panel does for you unless you untick **Add to Piper on connect**. See [Integrations](/connections/integrations).

## An app that is not in the catalog

Select **+ Add Custom** on the **Integrations** page. You can point Piper at any service that publishes an MCP server, the standard a service uses to offer its tools to an assistant like Piper, or at a program that runs on your Mac. [Integrations](/connections/integrations) covers that path.
