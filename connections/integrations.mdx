An integration is a connection between Piper and an app you already use, such as Gmail, Slack, or Notion. Each integration adds the app's own tools to Piper. Some tools look things up, and some change something.

Every integration uses the same standard. The app publishes the list of actions it offers in a form an assistant can call, and that standard is the Model Context Protocol, or MCP. A server that publishes actions this way is an MCP server. Each integration Piper ships is an MCP server Piper already knows how to reach and sign in to, and you can point Piper at any other service that publishes an MCP server.

## When to set up an integration

Set up an integration when the work you want Piper to do lives in that app. With Gmail set up, Piper can search your mail while it drafts a reply. With Notion set up, Piper can read the page a task refers to.

An integration is the only way Piper acts inside an app's own account. Without an integration, Piper can still open that app's website in [its own browser](/connections/web-and-sign-ins), which is slower and needs you to sign in there.

Piper also finds work to start before you ask in Gmail and Google Calendar. Once you connect either app, Piper reads it and puts the results on the Home page. Google Drive and your other apps give Piper context while it works. See [Work Piper starts before you ask](/working/before-you-ask).

[Integrations catalog](/reference/integrations-catalog) lists every app Piper ships an integration for, and what each app can do.

## Set up an integration

<Steps>
  <Step title="Open Integrations">
    In **Settings**, select **Integrations**. Piper lists the integrations you have set up under **Connected** and the rest under **Available**. Type into **Search integrations…** to filter both lists by name.
  </Step>
  <Step title="Pick the integration">
    Select its card to open its panel.
  </Step>
  <Step title="Work through the setup steps, if the panel shows any">
    For Atlassian and GitHub, the panel shows numbered steps to finish before you connect. For Gmail, Google Drive, Google Calendar, and Slack, the panel shows steps only when you choose to sign in through your own app. For Google, Slack, and GitHub, the panel also shows a link above the steps that opens that provider's developer portal.
  </Step>
  <Step title="Connect">
    Select **Connect**. For an integration you sign in to, approve the page that opens in your browser. For an integration that takes a key, paste the key first.
  </Step>
</Steps>

Piper then moves the integration to the **Connected** list. If you don't approve the sign-in page in time, the panel reads "Timed out waiting for sign-in to complete." Select **Connect** to start again.

To connect Gmail, Google Calendar, and Google Drive with one sign-in, select **Connect Google** on the Home page. Piper connects all three apps or none of them, so approve every permission Google asks for.

<Note>
  When you connect an app, Piper signs in and switches on that app's tools in the same step, each at the setting the app ships it with. Some tools stay switched off. Piper leaves the panel open on the tools, so you can review them and change any tool's setting straight away.
</Note>

<Warning>
  Piper holds one account per integration. If you connect a second Gmail account, Piper replaces the first account. You can't run a work account and a personal account side by side in the same integration.
</Warning>

## What an integration asks you for

Piper signs in to each integration in one of four ways, and the integration's panel shows which way.

| How Piper signs in | What you supply | Which integrations |
|---|---|---|
| Piper's built-in sign-in, or an app of your own | With the built-in sign-in, nothing: select **Connect** and approve the sign-in page. With your own app, the **Client id** and **Client secret** of an app you create in Google Cloud Console or in Slack's developer portal | Gmail, Google Drive, Google Calendar, and Slack |
| A sign-in in your browser | Nothing. Select **Connect** and approve the sign-in page that opens | Most other apps, including Notion, Linear, Asana, Todoist, Miro, Canva, Stripe, and Airtable. Atlassian also needs an administrator of your Atlassian organization to add Piper's address once, in numbered steps the panel gives you |
| A pasted key | An API key or access token you generate in that service. GitHub needs a fine-grained personal access token | Figma, Excalidraw, Firecrawl, and GitHub |
| Nothing at all | No account and no key | AWS Documentation |

### Sign in to Google or Slack through your own app

Piper's built-in sign-in for Gmail, Google Drive, Google Calendar, and Slack works only for approved users. If your account isn't approved, sign in through an app you register yourself:

<Steps>
  <Step title="Switch to your own app">
    In the integration's panel, select **Set up your own app instead**.
  </Step>
  <Step title="Create the app">
    Work through the numbered steps. The link above the steps opens Google Cloud Console for a Google app and Slack's developer portal for Slack. Copy the redirect address shown in the steps into your app's settings.
  </Step>
  <Step title="Connect">
    Paste the **Client id** and **Client secret**, select **Connect**, and approve the sign-in page in your browser.
  </Step>
</Steps>

To go back to the built-in sign-in, select **Use the built-in sign-in instead**.

<Note>
  Until Google finishes reviewing Piper, the Google sign-in page shows a warning that the app is unverified. Choose **Continue** to carry on. The sign-in then works as usual.
</Note>

<Warning>
  AWS Documentation reads public documentation and needs no account, but it runs through a developer tool called `uvx` that has to be installed on your Mac already. Piper checks for `uvx` when you select **Connect**. Where `uvx` is missing, Piper names it and stops without saving the connection. Piper can't install `uvx` for you, so you may need someone technical to set this integration up.
</Warning>

## What Piper may do once an integration is in place

Open a connected integration's panel to see its tools under **Tools**, in two groups. Each group shows how many of its tools are enabled.

- **Read** tools look things up: search your mail, list your issues, fetch a page. Piper sets most read tools to **Auto** and runs them on its own while it works. Piper sets a few read tools in Canva and Firecrawl to **Ask**.
- **Write** tools change something: send a message, create a task, update a record. Piper sets every write tool to **Ask**.

Open a group to see one entry per tool, with a checkbox and an **Auto** or **Ask** control. Clear a tool's checkbox to switch the tool off, or change its control.

The Gmail, Google Calendar and Google Drive tools that send email, change your calendar, share a file or comment on one show **Always ask** in place of that control. For these, Piper shows you a card in the conversation, and the action happens only when you select the button on it. Clear one of these checkboxes and Piper can't do that action at all, even from a card.

In Manual, Piper asks you before it runs a tool set to **Ask**. In Autopilot, Piper runs the tool without asking. See [Approvals and permissions](/control/approvals-and-permissions).

In tasks Piper starts on its own, Piper runs every tool you switched on without asking, including tools set to **Ask**. Gmail and Google Calendar are the exception. In those tasks, Piper withholds the Gmail and Google Calendar write tools. Piper sends a reply only when you select **Send**, and creates an event only when you select **Create event**. See [Work Piper starts before you ask](/working/before-you-ask).

<Warning>
  Piper leaves some tools switched off, including several tools that delete things. When Piper says in a task that it can't do something the app supports, open that integration's panel and switch the tool on.
</Warning>

Piper puts each integration's credentials in your Mac's keychain, one item per integration, and never shows them back to you.

Select **Disconnect** in an integration's panel to disconnect the app. Piper removes that app's tools and deletes the sign-in it stored, and you can set the integration up again at any time.

<Note>
  When you set up an integration, Piper reaches that app's own service over the internet. Piper keeps your tasks, files, and credentials on your Mac, and the app's data travels the same way it does when you use the app yourself. See [Your data stays local](/control/your-data-stays-local).
</Note>

## Reconnect an integration whose sign-in expired

An integration's sign-in can expire, and the sign-in saved on your Mac can go missing. Either way, Piper pauses that integration's tools until you sign in again. Piper also shows a banner across the top of the window, such as "Notion needs to reconnect." When several integrations need fixing, the banner shows how many instead. Select **Open Integrations** in the banner to go straight there.

The integration's card in the **Connected** list reads **Reconnect**. When you open the card, the panel shows that the sign-in expired. Select **Connect** to sign in again. Piper restores the integration as it was, including any tool settings you changed. To drop the integration instead, select **Remove**.

For an integration that takes a key, the panel says the app rejected the saved API key. Paste a new key and select **Connect**.

## Fix an integration that failed to start

Each connected integration runs on a server that Piper starts. When that server fails to start, Piper leaves that integration's tools out of new tasks. Piper also shows a banner across the top of the window, such as "Notion failed to start." When several integrations are affected, the banner shows how many instead. Select **Open Integrations** in the banner to go straight there. When an integration also needs a reconnect, Piper shows the reconnect banner first.

The integration's card in the **Connected** list reads **Failed to start**. Open the card to see the reason the server failed to start, such as a server that didn't answer in time or a command Piper couldn't run.

- Select **Retry** to start the server again now.
- Wait. Piper tries again on its own, with a longer gap before each new try.

Once the server starts, Piper clears the badge and puts the integration's tools back in new tasks. You can still change the integration's tools, or select **Disconnect**, while it shows **Failed to start**.

If a server you added yourself rejected your key, **Retry** isn't available. Disconnect the server and add it again with the right key.

## Add a server of your own

Where a service publishes an MCP server, you can point Piper at it and use its tools the same way as an integration Piper ships.

Select **+ Add Custom** at the top of the **Integrations** page, which opens **Add a custom server**. Fill in **Name**. Leave **Transport** on **Remote**, the setting for a server Piper reaches over the web, and paste the server's address into **Server URL**. Pick how Piper signs in under **Authentication**: **None**, **API key**, or **OAuth**. Select **Connect**. Piper signs in, asks the server what tools it offers, and sorts each tool into read or write for you.

<Tip>
  To add a server, you need details the service publishes: its address, and sometimes a key or an OAuth client ID. Get them from the service first. Where you choose **OAuth** and the server won't register Piper by itself, Piper says so and asks you to create an OAuth app with that provider. Paste the app's **Client ID** and **Client secret** under **Advanced** in the same panel, then select **Connect** again.
</Tip>

<Note>
  The other transport, **Local**, is for an MCP server that runs on your own Mac. For **Local**, you supply a **Launch config (JSON)**: the command that starts the server, its arguments, and any values the server needs. Use **Local** when the service gives you that configuration. When Piper can't run the command, Piper says so in the panel and saves nothing.
</Note>
