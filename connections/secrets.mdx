---
title: "Secrets"
description: "How to store a password, API key, or database credential once in your Mac's keychain, and how Piper uses it for one command without the value entering the conversation."
---

A secret is a named credential you save in Piper: a password, an API key, a database login. Each secret holds one or more fields, and a field is a short key with a secret value behind it. A database login might be one secret named `Warehouse` with the fields `HOST`, `USERNAME`, and `PASSWORD`. A single API key is a secret with one field.

## When to store a secret

Store a credential as a secret when a task needs to reach something Piper has no integration for: your own database, an internal service, a tool that asks for a token. If [Integrations](/connections/integrations) already covers the app, set it up there instead.

## The Secrets page

In **Settings**, select **Secrets** to see the secrets you have saved. Each card shows its name, its description, and how many fields it holds. Piper never shows a stored value again, so if you lose the original, get a new one from the service and replace the field.

## Where the value lives

Piper puts each field's value in your Mac's keychain, one keychain item per field. Piper's own database keeps the secret's name, its description, and the field keys, and holds no values at all. Nothing in Piper's interface can read a value back out.

## Store a credential

<Steps>
  <Step title="Open Secrets">
    In **Settings**, select **Secrets**.
  </Step>
  <Step title="Start a new secret">
    Select **New secret**.
  </Step>
  <Step title="Name it">
    Fill in **Name** with something you will recognize later, like `Warehouse`. **Description** is optional. A line such as `Snowflake prod, read-only` is what helps Piper pick the right secret for a task.
  </Step>
  <Step title="Add the fields">
    Under **Fields**, type a key, like `PASSWORD`, then its value. A key must start with a letter and use only letters, digits, and underscores, and Piper stores it in capitals. Select **Add field** for each further field.
  </Step>
  <Step title="Save">
    Select **Save secret**. Every value goes to the keychain at that moment.
  </Step>
</Steps>

## How Piper uses a secret

You do not do anything special. Ask for the work in plain words. Piper reads the list of what you have stored, picks the secret your task needs, and supplies its values to the one command that needs them.

What Piper reads from that list is names, descriptions, and field keys, never values. The values reach exactly one command, for as long as that command runs, and never enter the rest of Piper's work. Before that command's output comes back, Piper replaces every secret value in it with `•••`, so a credential cannot travel on into a chart, a file Piper writes, or a reply.

<Note>
  Very short values stay as they are in command output: anything under four characters, and plain numbers under six digits such as a port number. Masking those would blank out ordinary results.
</Note>

If your task needs a credential you have not stored yet, Piper names the missing secret and stops. Add it in **Settings** > **Secrets**, then ask again.

<Warning>
  A secret works only for a command running inside the task's own workspace folder. Piper refuses to run that command anywhere else, which is the same boundary every task writes inside. See [The sandbox](/control/sandbox).
</Warning>

## Change or remove a secret

Select the pencil icon on a card to edit that secret. You can change the name, the description, and the values, and you can add new fields. An existing field's key is fixed, and its value stays as it is unless you type a new one over the placeholder in its box.

Select the trash icon to delete a secret, then select **Delete** to confirm. Piper removes the secret and its stored values for good.

<Tip>
  Give each secret a name that says what it opens, not what kind of thing it is. `Warehouse` and `Stripe live` tell you what you are looking at later. `Key 1` does not.
</Tip>
