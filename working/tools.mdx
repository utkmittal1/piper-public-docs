A tool is a capability Copus can use while it works, such as reading a file, searching the web, running a command, or browsing a site. You control each capability with a checkbox in **Settings**, under **Built-in tools**. When you clear a checkbox, Copus can no longer use that capability.

Copus has some tools from the first message and looks up the rest as it works. Five of the seven capabilities are available from the start. Copus adds **Search knowledge** once a knowledge source holds indexed passages. Copus looks up **Browse websites** and a connected app's tools when a task needs them, so Copus loads Gmail's tools only in a task that uses Gmail.

Copus labels every step in the conversation in plain words, whichever AI provider runs the task. When Copus loads Gmail's tools, for example, the step reads **Looking up Gmail's tools**.

## Tell tools, skills, and integrations apart

These three settings sit next to each other and are easy to mix up.

- **Tools** are the capabilities Copus may use, such as reading a file, browsing a page, or acting in a connected app.
- **Skills** are the written instructions that teach Copus how to produce a particular kind of work, such as a slide deck or a dashboard. [Skills](/working/skills) covers them.
- **Integrations** are the apps you set up and sign in to, such as Gmail or Notion. [Integrations](/connections/integrations) covers them.

The three build on each other. Copus can't act in Gmail until you set Gmail up as an integration. You then switch each of Gmail's tools on or off on Gmail's panel under **Integrations**. Copus then follows a skill for how to do the work.

## See what Copus can do with no app connected

In **Settings**, select **Built-in tools**. The page lists seven capabilities, each with its own checkbox.

| Capability | Nature | What it does | Approval |
|---|---|---|---|
| Read files | read | Reads files and documents on this machine. | Always auto |
| Search files | read | Finds files by name and searches what's inside them. | Always auto |
| Web search & fetch | read | Searches the web and reads the pages it finds. | Always auto |
| Edit & write files | write | Creates and edits files in the folders this work can write to. | Auto or Ask, your choice |
| Run commands | write | Runs shell commands on this machine. | Always asks |
| Search knowledge | read | Searches the folders you added under Settings → Knowledge. | Always runs |
| Browse websites | write | Opens pages in Copus's own browser, and can click and fill them in. When a site needs you signed in, it opens a window so you can. | Always runs |

The approval column shows whether Copus stops to ask you. **Always auto** and **Always runs** both mean Copus goes ahead without asking. **Always asks** means Copus stops every time. The nature column shows whether the capability only looks at things or can change them.

You can change only one of those approval settings. On **Edit & write files**, you choose **Auto** or **Ask**. The setting starts on **Auto**, because the sandbox already limits those writes to the folders the task may write in. The approval on the other six rows is fixed.

When you switch on **Browse websites**, Copus shows an eighth checkbox beneath it, for working in the Chrome you use yourself. [Let Copus work in the Chrome you use](#let-copus-work-in-the-chrome-you-use) covers it.

A connected app's tools sit on that app's own panel under **Integrations**, where you switch a single tool off or change whether it asks. See [Integrations](/connections/integrations).

## Switch a capability off

<Steps>
  <Step title="Open the page">
    In **Settings**, select **Built-in tools**.
  </Step>
  <Step title="Switch a capability">
    Clear the checkbox next to a row to take that capability away. Tick it to give it back.
  </Step>
  <Step title="Set how writing is approved">
    On **Edit & write files**, choose **Auto** to let Copus write without asking, or **Ask** to be prompted each time.
  </Step>
</Steps>

Copus saves each change as you make it.

<Note>
Copus removes a capability you switched off from its toolset when a task starts. Switch a capability off while a task is already running, and Copus refuses that capability the moment the task tries to use it. **Search knowledge** is the exception. In a conversation already under way, Copus keeps using **Search knowledge** until it opens a new connection for that conversation, when you reopen the task later. These rules apply in **Autopilot** too. [Approvals and permissions](/control/approvals-and-permissions) covers the two approval modes.
</Note>

<Tip>
**Run commands** always asks, with one carve-out. Copus runs a command without asking when every part of it is one of these:

- a read-only program, such as `ls` or `git status`
- `mkdir`, creating a folder inside a folder the task can write to
- `cd`, into a folder the task can write to
- one of Copus's own skill scripts

Copus asks you about every other command. Copus also asks you about any command that names a file holding credentials, such as an `.env` file or a `.pem` key, whatever else the command does. Copus treats `.env.example`, `.env.sample`, and `.env.template` as ordinary files, because they hold placeholders. [Approvals and permissions](/control/approvals-and-permissions#what-copus-asks-every-time) lists the files Copus treats as credentials.

The carve-out also follows your switches. Switch **Read files** off, and Copus asks you before it runs a read-only command such as `cat`. Switch **Edit & write files** off, and Copus asks before it creates a folder.
</Tip>

## Choose the mode new tasks start in

The **Built-in tools** page has one more setting, **New tasks start in**. Every task you start from the message box begins in this mode. The **Ask Copus** drawer always runs in **Autopilot**. A new task starts in **Manual** until you change this setting.

In **Manual**, Copus asks you by default before it sends, posts, or changes anything in a connected app, and before it runs a command that changes something on your Mac. In **Autopilot**, Copus does these without asking. Copus asks you to confirm when you choose **Autopilot**, and switches back to **Manual** with no confirmation.

A task in a project you pointed at a folder of your own still starts in **Manual**, whatever this setting says.

You can change the mode of a single conversation from the dropdown under its message box, without touching this setting. [The message box](/working/describing-what-you-need) covers that control.

## Let Copus work in the Chrome you use

Copus has a browser of its own, and you switch it on with **Browse websites**. When you switch it on, Copus shows a nested checkbox beneath it, **Use my Chrome for sites I’m signed in to**. Tick it to let Copus work in the Chrome you're signed in to yourself.

Before you can tick that checkbox, you complete a one-time setup. Until then, the caption under the checkbox reads **Needs a one-time setup. Copus still asks you each time.** Select **Set up** on the same row. [Web and sign-ins](/connections/web-and-sign-ins) covers the browser extension that setup installs.

Copus asks you before it works in your Chrome on a site. One approval covers the rest of that request on that site, and the approval ends with the request. Copus asks every time, including in Autopilot, and never offers **Always allow in this conversation** for your Chrome. In tasks Copus runs with nobody watching, Copus refuses to use your Chrome. [Web and sign-ins](/connections/web-and-sign-ins) explains both browsers.

<Note>
The **Browse websites** row reads **Always runs**, and that holds for an ordinary page. On a site where Copus holds a saved sign-in, Copus asks you first, whatever the row says.
</Note>
