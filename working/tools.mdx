A tool is a capability Piper can use while it works, such as reading a file, searching the web, running a command, browsing a site, or sending mail in Gmail. You control each one with a checkbox. Clearing a checkbox removes that capability from Piper entirely.

Piper carries a handful of tools at all times and looks the rest up as it goes. The core capabilities below, and knowledge search, are in front of it from the first turn. A connected app's tools are not: Piper searches for the ones a task needs and loads them then, so a task that never touches Gmail never loads Gmail's tools. You see this in the conversation as a line reading **Looking up Gmail's tools**.

## Tools, Skills, and Integrations

These three settings sit next to each other and get mixed up constantly. Each does one job.

- **Tools** are the capabilities Piper may use. Whether it can read a file at all, browse a page at all, act in a connected app at all.
- **Skills** are the written instructions that teach Piper how to produce a particular kind of work, such as a slide deck or a dashboard. Covered on [Skills](/working/skills).
- **Integrations** are the apps you connect and sign in to, such as Gmail or Notion. Covered on [Integrations](/connections/integrations).

The order runs from one to the next. You connect Gmail under **Integrations**, and Gmail's actions appear on that same panel ready to use. A skill then decides how the work is done.

## What the Core Tools page holds

In **Settings**, select **Core Tools**. The page holds two things: what Piper can do on this machine, and the mode new tasks start in.

**Core Tools** are the seven capabilities Piper has without any app connected.

| Capability | Nature | What it does | Approval |
|---|---|---|---|
| Read files | read | Reads files and documents on this machine. | Always auto |
| Search files | read | Finds files by name and searches what's inside them. | Always auto |
| Web search & fetch | read | Searches the web and reads the pages it finds. | Always auto |
| Edit & write files | write | Creates and edits files in the task's own folder. | Auto or Ask, your choice |
| Run commands | write | Runs shell commands on this machine. | Always asks |
| Search knowledge | read | Searches the folders you indexed under Context → Knowledge Sources. | Always runs |
| Browse websites | write | Opens pages in Piper's own browser, and can click and fill them in. When a site needs you signed in, it opens a window so you can. | Always runs |

Use the checkbox on a row to turn that capability on or off. Only one approval setting is yours to change: **Edit & write files** offers **Auto** and **Ask**. The other six are fixed, as the right of each row shows.

**New tasks start in** is the other setting on the page. A new task starts in **Manual**, where Piper checks with you before it runs a command or acts in a connected app. Set it to **Autopilot** and every new task starts there instead. Piper asks you to confirm first. A project pointed at a folder of your own still starts its tasks in **Manual**.

A connected app's tools sit on that app's own panel. Connect Gmail under **Settings** > **Integrations** and Piper switches its tools on there, which is also where you switch one off or change whether it asks. See [Integrations](/connections/integrations).

## Turning a capability on or off

<Steps>
  <Step title="Open the page">
    In **Settings**, select **Core Tools**.
  </Step>
  <Step title="Switch a core capability">
    Clear the checkbox next to a row to take that capability away. Tick it to give it back.
  </Step>
  <Step title="Set how the write capability is approved">
    On **Edit & write files**, choose **Auto** to let Piper write without asking, or **Ask** to be prompted each time.
  </Step>
  <Step title="Choose how new tasks start">
    Set **New tasks start in** to **Manual** or **Autopilot**. Piper asks you to confirm when you choose **Autopilot**.
  </Step>
  <Step title="Change an app's tools">
    Open **Settings** > **Integrations** and select a connected app. Its **Read** and **Write** groups hold a checkbox and an **Auto** or **Ask** setting for every tool.
  </Step>
</Steps>

Every switch saves as you set it. Piper asks you to confirm only when you choose **Autopilot** as the start mode.

## What to know

<Note>
Off means off. A capability you switch off is removed from Piper's toolset when a task starts. Switch one off while a task is already running and the task is refused the moment it tries. **Search knowledge** is the exception: a conversation that already has it keeps it until it reconnects. Autopilot does not override any of this. [Approvals and permissions](/control/approvals-and-permissions) covers the two modes.
</Note>

<Tip>
**Run commands** always asks, with one carve-out. Piper runs a command on its own when every part of it is a read-only program such as `ls` or `git status`, a folder created inside the workspace, a `cd` into a folder inside it, or one of Piper's own skill scripts. Anything else reaches you as a question, and a command that names a file holding sign-in credentials reaches you whatever else it does. The carve-out follows your switches too: turning **Read files** off closes the route that would have read a file through a command instead, and turning **Edit & write files** off does the same for the silent folder creation.
</Tip>

<Warning>
Switch **Browse websites** on to reach the nested **Use my Chrome for sites I’m signed in to**, which takes a one-time setup before you can turn it on. Piper asks you before it works in your Chrome on a site, one approval covers the rest of that request on that site, and nothing carries past the request. Neither **Always allow** nor Autopilot can silence it. [Web and sign-ins](/connections/web-and-sign-ins) explains both browsers.
</Warning>

<Note>
**Browse websites** reads **Always runs**, which holds for an ordinary page. A site Piper holds a saved sign-in for asks you first, whatever the row says.
</Note>
