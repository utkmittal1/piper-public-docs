Piper answers in cards. A card is a block inside a reply holding one thing you can act on: a chart, a sortable table, a question, or a finished file. Piper draws ten kinds, and the actions on each are the point of this page, because most of them are not visible until you go looking.

## The ten kinds of card

| Card | What you can do with it |
| --- | --- |
| Chart | Hover a point for its values, then **Copy image**, **Save PNG**, **Save SVG**, **Copy data as CSV**, or **Copy chart spec** |
| Table | Sort by any column, filter, page through, **Copy table**, **Save as CSV**, or **Copy as markdown** |
| Diagram | **Copy image**, **Save PNG**, **Save SVG**, or **Copy markup** |
| Web page | A self-contained HTML page, such as a dashboard. Use it in place, **Save HTML**, or **Copy HTML** |
| Image | **Copy image** or **Save image** |
| File | A finished deliverable. **Open in default app**, **Show in Folder**, **Copy Path**, or **Copy Contents** |
| Plan | The steps Piper set itself, headed **Execution plan** |
| Question | Answer with a tap. A card asking more than one thing shows a `1 of 3` counter, and picking an option moves you to the next question rather than sending. Where a question takes several answers, tick what applies and select **Confirm** |
| Suggestions | Two to four follow-ups. Tap one to send it as your next message |
| Theme picker | The slide themes that ship with Piper. Tap one and Piper builds the deck in it |

Chart, diagram, image, and web page cards keep their actions hidden until you hover them. A table's sit in a bar above the rows and stay visible.

<Note>
  **Copy data as CSV** gives you the numbers behind a chart, and **Copy chart spec** gives you the chart's own description of itself, written in Vega-Lite, the grammar Piper draws charts with.
</Note>

<Note>
  A table draws at most 1,000 rows. Past that it reads **Showing first 1000 of 4312 rows**, so ask Piper for the whole result as a file when you need all of it.
</Note>

<Warning>
  If a card arrives damaged, or a reply ends early and cuts one off, ask Piper to draw it again.
</Warning>

## The file viewer

Select a file card and Piper opens the file beside the conversation, in a panel you can drag wider or narrower. The header shows the file name and its format on a badge, such as `PPTX`.

The viewer renders documents (`.docx`, `.pdf`, `.md`), spreadsheets (`.xlsx`, `.xls`, `.csv`), presentations (`.pptx`, `.ppt`), images, HTML pages, and plain text and code files. Anything else opens in whichever Mac app normally handles it.

A few formats behave in ways worth knowing before you go looking for a control that is not there.

- Spreadsheets open as a read-only grid. In a workbook with several sheets, select a sheet tab along the bottom to switch.
- Piper draws a presentation slide by slide, keeping the deck's own colours whichever Piper theme you use.
- A `.tsv` file opens as text rather than a grid.
- For a Markdown file, an HTML page, or a `.csv`, the panel offers **Preview** and **Source**. No other format has that toggle.

<Note>
  The viewer is read-only. To change a deck or a spreadsheet yourself, open it in the Mac app you usually use, or ask Piper for the change and let it rewrite the file.
</Note>

<Warning>
  Two size limits sit on the viewer. Above 50 MB, Piper will not open a file in the panel and tells you to open it in its usual Mac app instead. **Copy Contents** stops at 5 MB.
</Warning>

<Note>
  If Piper rewrites a file you already have open, select **Reload** in the panel header to see the new version. A card marked **No longer available** points at a file that has been moved or deleted since Piper wrote it.
</Note>

## Commenting on a passage

A comment is a note you attach to one passage of a document Piper wrote, and Piper reads the passage and the note together. Open the document, select the passage you disagree with, and a comment button appears next to it. Write your note and select **Add to chat**.

Your comment then sits above the message box as a chip showing the file name and what you wrote, with an × to drop it. Piper reads it with your next message. A comment also counts as a message on its own, so you can select **Send** with nothing typed and the notes are the message.

Where you can leave a comment depends on the file. Selecting a passage works in a Word file and in a Markdown file shown as **Preview**. Commenting on a particular line works in Markdown shown as **Source**, in an HTML page, in a spreadsheet or `.csv`, and in plain text and code files. PDFs, presentations, and images take no comments at all.

## Where the files themselves live

Piper writes finished work to the session's `final-output/` folder and working material to `intermediate-files/`, and both show up in the rail on the right under **Artifacts** and **Other files**. [Sessions and the workspace](/concepts/sessions-and-workspace) covers the folders in full.

Files stay on your Mac as ordinary files in ordinary folders. Attach a deliverable to an email, drop it in a shared drive, or edit it long after the task that made it has ended.

<Note>
  **Copy Path** and the path on a hovered row both give you the path inside the task folder rather than the full path on disk. Use **Show in Folder** when you need the file itself.
</Note>

## Drafts Chief of Stuff prepares for you

[Chief of Stuff](/autonomous/chief-of-stuff) never sends anything from the work it starts on its own. Piper refuses every integration's write tools inside that work, so a message written there comes back to you as a draft marked **Waiting**, showing where it is headed and the exact body that would go out. Nothing goes out until you select **Send** yourself.

<Warning>
  A task you started yourself works the other way. A session on **Autopilot**, which is where a new session starts, can send through a connected integration such as Gmail or Slack without showing you the message first. Switch the session to **Manual** when you want to see an outbound action before it happens. [Approvals and permissions](/control/approvals-and-permissions) covers both modes.
</Warning>
