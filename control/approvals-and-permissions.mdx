An approval is a request Piper puts in front of you before it acts. You decide which actions need an approval with two settings. You run each conversation in **Manual** or **Autopilot**, which you pick from the controls under the message box. Separately, Piper holds a list of tools, the individual things it can do, such as reading a file, running a command, or sending through Gmail. In **Settings**, you choose whether Piper asks before it uses each tool.

## Choose how much Piper does without asking

In **Manual**, Piper asks you by default before it sends, posts, or changes anything in a connected app, and before it runs a command that changes something on your Mac. In **Autopilot**, Piper does these without asking.

A new task starts in **Manual**. Switch it to **Autopilot** and only that conversation changes. The next task starts in **Manual** again. To start every new task on **Autopilot** instead, open **Settings**, select **Built-in tools**, and change **New tasks start in**. Piper asks you to confirm in a dialog headed **Start every new task on Autopilot?**.

Piper sets the mode itself for two kinds of conversation. A task in a project you pointed at a folder of your own starts in **Manual** whatever you set, because Piper writes that work into your own files. The [**Ask Piper**](/working/describing-what-you-need#ask-piper-a-quick-question) drawer runs on **Autopilot**, because Piper answers there on the spot.

<Steps>
  <Step title="Switch to Autopilot">
    Select **Autopilot** in the controls under the message box, then confirm with **Turn on Autopilot** in the dialog headed **Turn on Autopilot for this conversation?**. Select **Cancel** to back out.
  </Step>
  <Step title="Switch back to Manual">
    Select **Manual**. Piper applies the change straight away, without asking you to confirm, including to a task already running.
  </Step>
</Steps>

Piper reads the mode fresh for each request, so Piper applies a switch from the next action of a running task.

<Warning>
  On **Autopilot**, Piper can send an email through Gmail, post to a Slack channel, or change a record in any other app you have connected, without showing you the message first. Use **Manual** wherever a message going out would matter.
  When you ask for an email or a meeting, Piper usually drafts it as a card in the conversation instead, and nothing goes until you send it from the card.
</Warning>

<Tip>
  Start a sensitive task on **Manual**, watch the first few actions, then switch to **Autopilot** once you can see what Piper is doing.
</Tip>

## What Piper does without asking

Piper does these without asking, in both modes. It reads a file, searches your files, searches the web, fetches a page, searches your Knowledge Sources, writes a file inside the folder the task can write to, and opens a page in a browser of its own. These actions change nothing outside the task. If Piper asked before each action, you would learn to approve questions without reading them.

Piper also runs a fixed list of read-only programs on its own: `ls`, `pwd`, `cat`, `head`, `tail`, `wc`, `grep`, `rg`, `which`, `whoami`, `date`, `file`, `stat`, `basename`, `dirname`, `echo`, `du`, `df`, and `pdftotext`, plus git's own reading verbs, `git status`, `git log`, `git diff`, and `git show`. All but one of those programs only print what is already there. `pdftotext` writes the text it pulls out of a PDF, inside the folder the task can already write to. Piper runs two more programs without asking in one use each: `sed` when it prints a range of lines, and `pandoc` when it only converts a file. Piper can also create a folder inside the folder it writes to, change directory inside that folder, and run one of its own bundled scripts through the Python it ships.

Piper keeps that list narrow on purpose. It asks about any command that redirects output, refers to a shell variable, or builds part of itself from the output of another command, because each of those hides what the command will really touch. Piper allows one variable without asking, the variable naming the Python it ships, because that variable stands for a fixed path Piper wrote. Piper runs a chain of commands without asking only where every part of the chain qualifies on its own. If any single program is off the list, Piper asks you about the whole command.

Piper reads through an integration without asking as well. An integration is the connection Piper holds to an app such as Gmail, Slack, or Linear. Each integration has its own set of tools. Piper sets an integration's reading tools to run on their own, and its writing tools to ask, when you first connect the app.

## Why file writes run without asking

Piper writes a file inside the task's folder without asking, in both modes. The mode sets how Piper handles a request. Piper writes inside the folder without raising a request, so file writes run the same way in **Manual** and on **Autopilot**.

The folder sets which of your files a write can change. For a task outside a project, the folder is that task's workspace, so your other files stay as they are. For a task in a project you pointed at a folder of your own, the folder is that whole folder of yours. Piper creates files in it, and writes over files you already had, without asking.

You can limit these writes in two ways. Set **Edit & write files** to **Ask** on the **Built-in tools** page and Piper raises a request before each write. In **Manual**, the task waits until you answer. On **Autopilot**, Piper answers the request itself. Piper also raises a request before a command that deletes files, such as `rm`, because Piper asks before every command outside the read-only list. The command waits for you in **Manual** and runs on **Autopilot**. Otherwise, point a project only at a folder you're happy for Piper to change.

## What Piper asks about

Piper asks before every command outside the read-only list, and shows you the exact command in the request. It also asks before anything an integration writes, such as a Gmail message, a Slack post, or a new or changed Linear issue.

Piper browses ordinary pages in a browser of its own without asking. It asks the moment that browser lands on a site you have signed in to through Piper, because that page is your account. That request is an ordinary approval request, so on **Autopilot** Piper answers it for you.

## What Piper asks every time

Piper asks two questions every time they come up. On both questions, Piper waits for your answer, including on **Autopilot**, and leaves out **Always allow in this conversation**.

**Reading a file that holds credentials.** Piper asks before a task reads any of these:

- A `.env` file, or a file whose name starts with `.env.`, such as `.env.local`. Piper reads a template whose name ends in `.example`, `.sample`, or `.template`, such as `.env.example`, without asking.
- A `.pem`, `.key`, `.p12`, or `.pfx` file.
- A key file named `id_rsa`, `id_dsa`, `id_ecdsa`, or `id_ed25519`.
- A file named `credentials`, `credentials.json`, or `auth.json`, or a file named `secret` or `secrets` that ends in `.json`, `.yaml`, `.yml`, or `.toml`.
- Anything in your keychain folder, `~/Library/Keychains`.
- The sign-ins Piper keeps in `PiperData`: the `.claude` and `.codex` folders, and the folders where Piper's browser keeps the logins for sites you signed in to. Piper reads one kind of file in the `.claude` folder without asking: the files where Claude Code saves a command's output when the output is too long to show.

Piper adds whatever a task reads to the conversation and sends the conversation to your AI provider, so Piper leaves this read to you. Piper checks both routes to a file: the file a tool names, and the file a command names in its arguments.

Piper asks this question about a credential file in a folder of your own. Piper refuses a file inside one of the folders it keeps shut, such as `~/.ssh` or `~/.aws`, without asking you. For every folder and file Piper keeps shut, see [The sandbox](/control/sandbox).

**Working in the Chrome you are signed in to.** Piper works in your own Chrome only after you switch on **Use my Chrome for sites I’m signed in to** under **Built-in tools**, which needs a one-time browser extension. Even then Piper asks before it acts on each site, and your answer covers that one site for the rest of the turn. A turn is one round of work: your message, and everything Piper does before it comes back to you. Send the next message and Piper asks again.

Piper applies the opposite rule to work it runs with nobody watching. In that work, Piper refuses your own Chrome, and refuses a credential file the moment the question comes up, because nobody is there to answer. Piper applies this rule to a run of a scheduled task, a long-running task, the conversation behind **Ask Piper** on a scheduled task's page, and every task Piper starts on its own.

## Answer a request

Piper shows the request in the conversation under **Approval needed**, with one line naming the action. Where the exact command or file path adds something the line doesn't already say, select **Details** to see it.

Under that, choose one of three buttons:

- **Deny**: Piper blocks the action.
- **Always allow in this conversation**: Piper takes the action, and answers the same question itself for the rest of that conversation. Piper shows this button only where it can remember the answer.
- **Allow**: Piper takes that one action.

When the action has a scope, Piper names it on the middle button. Approve a `pip install` and the button reads `Always allow “pip install” in this conversation`. The scope is the program rather than the exact command line, so the same approval covers installing a different package. For programs that bundle many verbs, the scope is the program plus the verb. These programs are `git`, `npm`, `pnpm`, `yarn`, `pip`, `pip3`, `uv`, `brew`, `docker`, `cargo`, and `go`. Approving `pip install` therefore does nothing for `git push`.

Once you've used that button, Piper lists everything you allowed under **Allowed tools** in the conversation's right-hand rail, each as a chip. Remove a chip and Piper asks about that action again. What you allow holds for that one conversation, including after you close Piper and come back to it. Piper never applies it to another conversation.

<Warning>
  If you leave a request unanswered, Piper denies it after a set time. The card then reads **Auto-denied**, and the task carries on as though you had selected **Deny**. If you leave a task mid-approval, you come back to find that action refused. Select the × on the card to clear it from the conversation.
</Warning>

## Set each tool on its own

The mode covers every question at once. You can also set permissions one tool at a time, and Piper keeps those settings across tasks.

In **Settings**, select **Built-in tools**. The page lists what Piper can do on this machine, alongside the mode new tasks start in. Each row shows whether Piper asks before it uses that capability. Clear a row's checkbox and Piper builds your tasks without that capability.

You can't set **Run commands** to run on its own. A task can read files and reach the network, so Piper's question before a command is the check that stops a task from sending your data somewhere. **Edit & write files** is the one row whose **Auto** or **Ask** setting you can change.

See [Built-in tools](/working/tools) for each capability and its checkbox. See [Integrations](/connections/integrations) for a connected app's own tools, which you set on that app's panel in its **Read** and **Write** groups, each with a checkbox and an **Auto** or **Ask** setting.

## Limits that hold in both modes

On **Autopilot**, Piper answers the ordinary questions for you. A task on **Autopilot** can do only what it could do in **Manual**, and these limits hold in both modes.

**The sandbox holds on Autopilot.** macOS refuses a write outside the folder the task can write to, with no question to you, so **Autopilot** can't allow the write. [The sandbox](/control/sandbox) covers that boundary.

**A tool you switched off stays off.** Clear the checkbox beside **Run commands** and Piper builds your next task without it. **Autopilot** can't bring the tool back, because the task doesn't have it.

**Piper asks about credential files and your own Chrome in both modes.** Piper leaves both to you, in **Manual** and on **Autopilot**.

<Note>
  Tasks Piper starts on its own follow a rule of their own. Piper runs these tasks on **Autopilot**, and gives them only the reading tools for Gmail and Google Calendar. Piper sends a reply only after you select **Send** on the task, and creates an event only after you select **Create event**. In your other connected apps, Piper uses every tool switched on for that app, and uses a tool set to **Ask** without asking you first. See [Work Piper starts before you ask](/working/before-you-ask).
</Note>
